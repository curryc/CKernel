# 

64bit虚拟地址被分割：
|63-48|47-39|38-30|29-21|20-12|11-0|
|---------|---------|---------|---------|---------|---------|
| 符号扩展(全 1)|  PML4 9 |  PDPT 9 |   PD 9  |   PT 9  | 12 bit  |
|  (must = 1)   |  bits   |  bits   |  bits   |  bits   | offset  |

如何通过虚拟地址寻址：
| 步骤 | 目录                           | 你手里的“页码”        | 得到的新线索             |
| -- | ---------------------------- | --------------- | ------------------ |
| ①  | **PML4** (Page-Map Level-4)  | PML4 索引 (9 bit) | 一张 **PDPT** 的物理地址  |
| ②  | **PDPT** (Page-Directory-PT) | PDPT 索引 (9 bit) | 一张 **PD** 的物理地址    |
| ③  | **PD** (Page-Directory)      | PD 索引 (9 bit)   | 一张 **PT** 的物理地址    |
| ④  | **PT** (Page-Table)          | PT 索引 (9 bit)   | 一条 **PTE**（64 bit） |
| ⑤  | 页地址 **4 kB 内存**              | 12 bit offset   | 真正的 **字节**         |


一条pte的64bit长什么样：
|63-52|51-12|11-9|8|7|6|5|4|3|2|1|0|
|-----------|-------------------------|---|---|---|---|---|---|---|---|---|---|
| 保留：可用/脏位软件 |  Physical Frame Number  |AVL| G |PS| D | A |PCD|PWT|U|W|P|

其中的含义：
|bit 缩写|含义|说明|
|-------|-------|-------|
|P (0)|Present|1 = 该页/表有效，0 = 无效|
|W (1)|Read/Write|0 = 只读，1 = 可写|
|U (2)|User/Supervisor|0 = 仅 CPL0 可访问，1 = 任意 CPL|
|PWT (3)|Page Write-Through|1 = 写通（cache 策略）|
|PCD (4)|Page Cache Disable|1 = 关闭缓存|
|A (5)|Accessed|CPU 在第一次访问后置 1|
|D (6)|Dirty|仅末级 PTE 有效，写访问后置 1|
|PS (7)|Page Size|仅 PD/PDPT 级 1 = 大页（2 MiB/1 GiB）|
|G (8)|Global|1 = 全局 TLB 项，需 CR4.PGE=1|
|AVL (9-11)|Available|软件随意使用|
|PFN (12-51)|Physical Frame Number|下一级表 或 最终页的 物理地址（4 KiB 对齐）|
|NX (63)|No-eXecute|1 = 不可执行，需 EFER.NXE=1|

举例说明如何寻址：

假设：
+ 虚拟地址 = 0xFFFF'8000'1234'5678
+ 已建好 4 级页表，CR3 指向 PML4 物理地址 0x1F'000

步骤：
1. 把地址拆 5 段：PML4=256，PDPT=0，PD=0，PT=35，offset=0x678
2. CPU 读 CR3 → 拿到 PML4 物理页 0x1F'000，乘 8 字节偏移 → 读 0x1F'000 + 256×8 得到一条 PDPT-PTE，假设值 0x20'003（P=1，PFN=0x20）
3. 这条 PTE 告诉 CPU：PDPT 页在 0x20'000，再读 0x20'000 + 0×8 → 拿到 PD-PTE 0x30'003
4. 再读 0x30'000 + 0×8 → 拿到 PT-PTE 0x40'003
5. 再读 0x40'000 + 35×8 → 拿到最终 PTE 0x7F'E00'003，其中 PFN=0x7F'E00
6. 物理页首地址 = 0x7F'E00'000，加上 offset 0x678 → 真正字节在 0x7F'E00'678
