# 中断的原理
## CPU需要中断
中断是指外部或者内部事件打断CPU正在执行的流程，迫使CPU区执行一个特定的中断服务程序。
中断服务程序执行完毕，CPU会继续执行中断前的程序。
中断服务是必要的，它让CPU有能力面对外部或者内部事件。
重要的比如：键盘输入，鼠标点击和硬盘读写，网络传输等硬件中断，
也有如系统调用，系统异常等软件中断。

## 中断流程
中断开始于一个中断请求信号，CPU中存在一个中断控制器，这个控制器会向CPU发送一个中断请求信号，CPU收到这个信号后，会进行中断处理。
中断处理流程如下：
1. 中断响应：CPU完成当前指令后，检查中断标志位，若允许中断，则响应。
2. 保存现场：CPU将当前程序的PC（程序计数器）、寄存器状态等压入栈中，保存上下文。
3. 跳转到中断服务程序：根据中断向量表找到对应的中断处理程序入口地址。
4. 执行中断服务程序：处理中断事件（如读取键盘输入、处理网络包等）。
5. 恢复现场：执行完毕后，从栈中恢复之前保存的寄存器和PC。
6. 继续原程序：CPU回到中断前的状态，继续执行原程序。

显而易见的是，中断的处理需要保存和恢复现场，并且每个中断处理程序存在区别。
所以中断的设计应该有统一的出入口，但是内部要有拓展空间来满足不同的中断处理请求。
# 中断模块的结构设计
显然中断需要汇编指令和CPP配合才可以，汇编中完成中断的注册和入口调用，CPP代码中完成中断处理。
在汇编中，首先需要的是中断的注册代码，向cpu注册中断服务程序入口，这样cpu才知道此中断的入口。
```asm
idt_load:
    // 非空检查
    test    %rdi, %rdi
    jz      1f
    // limit 必须 ≥ 8*N-1  (N 个描述符，最小 8*1-1=7)
    movw    (%rdi), %ax         /* limit */
    cmpw    $7, %ax
    jb      1f                  /* < 7 直接失败 */
    // base 必须 16 字节对齐
    movq    2(%rdi), %rax
    test    $0xF, %rax
    jnz     1f
    // 加载idt
    lidt    (%rdi)
    // 成功
    xor     %rax, %rax
    ret
    // 失败
1:  mov     $-1, %rax
    ret
```
这里的idt_load有对输入参数的检测，其中的lidt指令即是加载idt指令。告诉cpu此中断的入口。
如果中间某一步没有通过检测，将会跳转到的1：，返回-1。

```asm
// ss~rip 由 CPU 压入
.macro pusha_64
    push %rax
    push %rbx

    push %r15
.endm

.macro popa_64
    pop %r15
    pop %r14
    pop %r13
    pop %r12
    pop %r11
    pop %r10
    pop %r9
    pop %r8
    pop %rbp
    pop %rdi
    pop %rsi
    pop %rdx
    pop %rcx
    pop %rbx
    pop %rax
.endm
.macro ISR_NO_ERROR_CODE no
isr\no:
    // 关中断
    cli
    // 保存现场
    pusha_64
    // 传递中断号
    mov $\no, %rdi
    // 传递 
    mov %rsp, %rsi
    // 清零
    xor %rdx, %rdx
    xor %rbp, %rbp
    // 调用处理函数
    call isr_handler
    // 恢复现场
    popa_64
    // 中断返回
    iretq
.endm
.macro ISR_ERROR_CODE no
isr\no:
    // 关中断
    cli
    // 压栈 intr_context_t 的最后几个成员
    // 40(%rsp) 是因为每次压栈都会使 rsp+8，执行完后 rsp 刚好移动到下一个数据
    // 在 64 位模式下，不论特权级是否改变，都会压入 ss，rsp
    // 64-ia-32-architectures-software-developer-vol-3a-manual#6.14.2
    // SS
    push 40(%rsp)
    // RSP
    push 40(%rsp)
    // RFLAGS
    push 40(%rsp)
    // CS
    push 40(%rsp)
    // RIP
    push 40(%rsp)
    pusha_64
    // 传递中断号
    mov $\no, %rdi
    // 传递栈地址
    mov %rsp, %rsi
    // 传递错误码
    // 160==sizeof(intr_context_t)
    // 相当于函数开始时的 0(%rsp)
    mov  160(%rsp), %rdx
    xor %rbp, %rbp
    call isr_handler
    popa_64
    iretq
.endm
```
cpu在遇到中断时，首先关闭中断，防止中断嵌套。然后保存现场，将寄存器压入栈中。最后在调用对应的中断处理程序，跳转到c++函数中。
需要注意的是，这里使用了宏来生成多个中断处理函数，其中的\no表示中断号，也是用来给宏生成中断函数的参数。
在进入中断处理程序的时候，最好能将中断的上下文也传递进去，让中断处理程序可以获取中断的详细上下文，方便处理。
所以在ISR_ERROR_CODE宏中，将上下文也传递到了isr_handler中。

x86_64的idt条目结构是固定的：
```c
    struct idt_entry_t
    {
        uint16_t offset_low;  // 偏移低16位
        uint16_t selector;    // 代码段选择子
        uint64_t ist : 3;     // 中断栈表
        uint64_t zero0 : 5;   // 填充 0
        uint64_t type : 4;    // 类型
        uint64_t zero1 : 1;   // 填充 0
        uint64_t dpl : 2;     // 权限
        uint64_t p : 1;       // 存在位
        uint16_t offset_mid;  // 偏移中16位
        uint32_t offset_high; // 偏移高32位
        uint32_t reserved;    // 保留必须为0
    } __attribute__((packed));
```
需要做的就是创建我们需要的条目并将其注册到cpu中，因此我们创建一个数组，并循环写idt条目，然后给直接调用idt_load即可
```c++
void INTERRUPTS::make_idt_entry(uint8_t vec, void (*handler)(), uint8_t type, uint8_t dpl, uint8_t _p)
{
    uint64_t addr = reinterpret_cast<uint64_t>(handler);
    idt[vec].offset_low = addr & 0xFFFF;
    idt[vec].selector = 0x08; // 假设平坦模型代码段
    idt[vec].ist = 0;
    idt[vec].zero0 = 0;
    idt[vec].type = type; // 0xE=中断门, 0xF=陷阱门
    idt[vec].zero1 = 0;
    idt[vec].dpl = dpl;
    idt[vec].p = _p;
    idt[vec].offset_mid = (addr >> 16) & 0xFFFF;
    idt[vec].offset_high = (addr >> 32) & 0xFFFFFFFF;
    idt[vec].reserved = 0;
}
```

注册完毕后，cpu每次遇到中断信号变换进入c++的中断处理程序，最终将会跳转到以下函数中：
```c++
int32_t INTERRUPTS::call_isr(uint8_t _no, intr_context_t* _intr_context)
{
    if (_no < EXCP_MAX && interrupt_handlers[_no] != nullptr)
    {
        interrupt_handlers[_no](_no, _intr_context);
        return 0;
    }
    return -1; // 未找到处理函数
}
```
所以，还需要对interrupt_handlers进行初始化，才能找到每个中断特有的处理函数，在最开始，直接给所有中断使用默认的中断函数即可。
```c++
    void isr_default_handler(INTERRUPTS::intr_context_t *)
    {
        while (1)
        {
            ;
        }
        return;
    }
```
如果想要注册一个新的中断，只需要更改interrupt_handlers数组即可。
在特定的中断index定义一个函数，最终将会跳转到此函数并执行。
# PIC初始化与原理
显然，中断的类型可能是会很多的。

形象点来说，中断就像一个个事物，CPU就是办公室的经理和控制者，各种不同类型数量庞大的中断传递而来，会让CPU陷入一直处理中断的状态，
所以，会给CPU配备一个“秘书”、“仲裁”，即PIC，它负责将中断进行一次过滤，比如中断的优先级，中断屏蔽和多路复用等等。

PIC的硬件结构比较经典的是级连两片的结构：主片（Master）负责IRQ0到IRQ7，从片（Slave）负责IRQ8到IRQ15。
从片通过IRQ2引脚向主片传递信号，级联到主片上。

因此，外部的中断想要打断cpu，必须对pic进行配置才行，不然pic可能会直接过滤到中断信号，导致cpu无法处理。
初始化pic的代码：
```c++
void INTERRUPTS::pic_init()
{
    /* ICW1：级联，需要 ICW4 */
    PORT::port_outb(PIC1_COMMAND, 0x11);
    PORT::port_outb(PIC2_COMMAND, 0x11);

    /* ICW2：中断向量偏移 0x20 / 0x28 */
    PORT::port_outb(PIC1_DATA, 0x20);
    PORT::port_outb(PIC2_DATA, 0x28);

    /* ICW3：主片 IRQ2 级联从片；从片 ID=2 */
    PORT::port_outb(PIC1_DATA, 0x04);
    PORT::port_outb(PIC2_DATA, 0x02);

    /* ICW4：8086 模式 */
    PORT::port_outb(PIC1_DATA, 0x01);
    PORT::port_outb(PIC2_DATA, 0x01);

    /* 屏蔽所有 IRQ*/
    PORT::port_outb(PIC1_DATA, 0xFF);
    PORT::port_outb(PIC2_DATA, 0xFF);
}
```
如果想要不屏蔽某些IRQ，则需要更改pic的屏蔽位，让某个位置为0，表示允许该中断。

# APIC初始化和原理
PIC是一个很好的秘书，但是有一定的局限性，引入了APIC，主要有以下这些优势：
1. 多核中断支持，APIC可以把任意中断投递到任意核心，实现多核负载均衡，满足现代CPU设计
2. 软件可调的中断优先级，不像PIC固定的优先级设置，APIC可以在软件中动态调控
3. 引脚多，15个引脚到24个引脚，并且每个核心都有256个向量，大大提高中断处理效率
4. 调度器，MSI支持，PCIE口标配
5. 消息中断可以随核休眠，降低功耗，实现设备的深度idle模式

总之，APIC更能满足当代CPU架构设计，
