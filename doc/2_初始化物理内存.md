# 1. 硬件信息的传递
multiboot2会在内存中储存内核需要的信息，并将地址储存在寄存器中，在boot.S中有如下代码：
```
.extern boot_info_addr
.extern multiboot2_magic
_start:
    cli
    // multiboot2_info 结构体指针
    mov %ebx, boot_info_addr
    // multiboot2_magic魔数
    mov %eax, multiboot2_magic
```
此代码对boot_info_addr和multiboot2_magic两个变量进行赋值，将寄存器中的地址赋给这两个变量，方便在cpp代码中进行访问解析

# 2. 解析内核信息
进入kernel_main后的第一步就是解析内核信息，这样才能进行后续的物理内存初始化和分页操作。
在BOOT_INFO::init函数中，上面的两个变量会被用于验证和解析。
首先，需要验证魔数是否正确，这是不可缺少的一步，要确保信息是有效的。

```
bool MULTIBOOT2::multiboot2_init(void)
{
    uintptr_t addr = BOOT_INFO::boot_info_addr;
    
    // 判断魔数是否正确
    if (BOOT_INFO::multiboot2_magic != MULTIBOOT2_BOOTLOADER_MAGIC) {
        vga_printf("multiboot2_init: Invalid magic number! Expected: 0x%x, Got: 0x%lx\n", 
                   MULTIBOOT2_BOOTLOADER_MAGIC, BOOT_INFO::multiboot2_magic);
        return false;
    }
    
    // 修复地址对齐检查
    if ((addr & 7) != 0) {
        vga_printf("multiboot2_init: Address not aligned! addr=0x%lx\n", addr);
        return false;
    }
    
    // 空指针检查
    if (addr == 0) {
        vga_printf("multiboot2_init: Boot info address is NULL!\n");
        return false;
    }
    
    // 检查地址是否在合理的内存范围内
    if (addr < 0x100000 || addr > 0x1000000) {  // 1MB到16MB之间
        vga_printf("multiboot2_init: Boot info address out of range! addr=0x%lx\n", addr);
        return false;
    }
    
    // 内存读取
    uint32_t size = 0;
    uint8_t* size_ptr = (uint8_t*)addr;
    for (int i = 0; i < 4; i++) {
        size |= (uint32_t)(size_ptr[i]) << (i * 8);
    }
    
    BOOT_INFO::boot_info_size = size;
    
    // 验证大小是否合理
    if (BOOT_INFO::boot_info_size < 8 || BOOT_INFO::boot_info_size > 65536) {
        vga_printf("multiboot2_init: Boot info size unreasonable: %d\n", BOOT_INFO::boot_info_size);
        return false;
    }
    return true;
}
```
初始化完成后，如果验证通过，可以进行后的物理内存初始化操作。

# 3. 获取物理内存信息
## 获取可用内存的原理
multiboot2在固定的内存空间中储存有不同的tag，每个tag都固定在开始的四个字节包含两个字段：tag type和tag size。
通过tag type和tag size，可以判断tag的类型，并遍历所有的tag，直到找到可用内存的tag。
对于内存tag而言，相关代码如下：
```
    static constexpr const uint32_t MULTIBOOT_TAG_TYPE_MMAP = 6;

    struct multiboot_tag_t
    {
        uint32_t type;
        uint32_t size;
    };
    struct multiboot_mmap_entry_t
    {
        uint64_t addr;
        uint64_t len;
        uint32_t type;
        uint32_t zero;
    };
    struct multiboot_tag_mmap_t : multiboot_tag_t
    {
        uint32_t entry_size;
        uint32_t entry_version;
        multiboot_mmap_entry_t entries[0];
    };
```
如果tag的type等于MULTIBOOT_TAG_TYPE_MMAP，则说明是可用内存tag，以此获取可用内存信息。
每个entry包含后内存的地址、长度、类型和保留字段(0位)。
## 获取可用内存的方法
显然，我们需要遍历所有的tag，如果有tag的type等于MULTIBOOT_TAG_TYPE_MMAP，则说明是可用内存tag，再进行进一步的处理。
所以，对于multiboot2传递来的boot_info_addr：
```
    uintptr_t    addr = BOOT_INFO::boot_info_addr;
    iter_data_t* tag  = (iter_data_t*)(addr + 8);
    for (; tag->type != MULTIBOOT_TAG_TYPE_END;
         tag = (iter_data_t*)((uint8_t*)tag + common::ALIGN(tag->size, 8))) {
        if (_fun(tag, _data) == true) {
            return;
        }
    }
    return;
```
每次移动一个tag，指导找到正确的tag即可。
这里的_fun和_data参数，分别表示处理当前tag的函数的传递的tag。
对应到可用内存中，此函数如下：
```

bool MULTIBOOT2::get_memory(const iter_data_t *_iter_data, void *_data)
{
    if (_iter_data->type != MULTIBOOT2::MULTIBOOT_TAG_TYPE_MMAP) {
        return false;
    }

    resource_t *resource = (resource_t *)_data;
    resource->type |= resource_t::MEM;
    resource->name = (char *)"available phy memory";
    resource->mem.addr = 0x0;
    resource->mem.len = 0;

    // 获取 mmap 标签
    multiboot_tag_mmap_t *mmap_tag = (multiboot_tag_mmap_t *)_iter_data;
    uint32_t tag_size = mmap_tag->size;
    uint8_t *tag_end = (uint8_t*)mmap_tag + tag_size;
    uint32_t entry_size = mmap_tag->entry_size;

    // 验证基本参数
    if (entry_size == 0 || tag_size < sizeof(multiboot_tag_mmap_t)) {
        vga_printf("multiboot2_get_memory: Invalid mmap tag parameters\n");
        return false;
    }

    // 指向第一个内存映射项
    MULTIBOOT2::multiboot_mmap_entry_t *mmap = (MULTIBOOT2::multiboot_mmap_entry_t *)
        ((uint8_t*)mmap_tag + sizeof(multiboot_tag_mmap_t));

    // 计算实际可以访问的条目数量
    size_t max_entries = (tag_size - sizeof(multiboot_tag_mmap_t)) / entry_size;

    // 遍历所有内存映射项 - 使用更安全的遍历条件
    for (size_t i = 0; i < max_entries; i++) {
        // 检查是否还有足够的空间读取完整的条目
        if ((uint8_t*)mmap + sizeof(MULTIBOOT2::multiboot_mmap_entry_t) > tag_end) {
            vga_printf("multiboot2_get_memory: Reached tag boundary, stopping\n");
            break;
        }

        // 验证内存区域的有效性
        if (mmap->len == 0) {
            mmap = (multiboot_mmap_entry_t*)((uint8_t*)mmap + entry_size);
            continue;
        }

        // 如果是可用内存
        if (mmap->type == MULTIBOOT_MEMORY_AVAILABLE) {
            // 累加可用内存大小
            resource->mem.len += mmap->len;
        }
        // 移动到下一个内存映射项
        mmap = (multiboot_mmap_entry_t*)((uint8_t*)mmap + entry_size);
    }
    return true;
}
```
通过type判断是MULTIBOOT_TAG_TYPE_MMAP后，找到每一个entries，并对entries遍历处理，如果是可用内存：MULTIBOOT_MEMORY_AVAILABLE，便添加到resource中。
通过多次遍历，得到最终的可能内存大小。

## 初始化分配器
得到可用内存后，需要设置分配器，用于后续对内存进行分配。
再初始化分配器之前，首先需要区分内核空间和用户空间，以避免内核空间被用户空间所占用，导致不必要的安全问题。
```
    // 计算页数
    total_pages = length / common::PAGE_SIZE;
    // 内核空间地址开始
    kernel_space_start = common::KERNEL_START_ADDR;
    // 长度手动指定
    kernel_space_length = common::KERNEL_SPACE_SIZE;
    // 非内核空间在内核空间结束后
    non_kernel_space_start = common::KERNEL_START_ADDR + common::KERNEL_SPACE_SIZE;
    // 长度为总长度减去内核长度
    non_kernel_space_length = length - kernel_space_length;
```
所以也需要两个内存分配器，用于对两个空间进行内存管理，首先使用最简单first fit算法写一个内存分配器。
如下为first fit算法的alloc方法，核心思想是通过遍历数组，找到第一个满足条件的节点，并返回该节点。
通过使用一个数组，数组中每一个bit表示一个页，bit为1表示该页被占用，bit为0表示该页可用。
first fit：只要找到即用。
```
uintptr_t FIRSTFIT::alloc(size_t _len) {
    uintptr_t res_addr = 0;
    // 在位图中寻找连续 _len 的空闲位置
    size_t    idx      = find_len(_len, false);
    // 如果为 ~0 说明未找到
    if (idx == ~(size_t)0) {
        return res_addr;
    }
    // 遍历区域并置为使用
    for (auto i = idx; i < idx + _len; i++) {
        // 置位，说明已使用
        set(i);
    }
    // 分配器起始地址+页长度*第几页
    res_addr              = allocator_start_addr + (common::PAGE_SIZE * idx);
    // 更新统计信息
    allocator_free_count -= _len;
    allocator_used_count += _len;
    return res_addr;
}
```
first fit算法几乎是最简单的内存管理方法了，代码简单但是会存在大量的碎片。
同时循环遍历的存在可能会导致时间复杂度过长，后续如果无法满足需求可能需要更高效的算法。

## 将multiboot2的硬件信息调到内核空间
由于后续存在的内存映射问题，0-1M中储存的multiboot2硬件信息可能无法直接访问，因此有必要将其搬到内核空间中。
而且，将内核需要的内容放到内核空间是符合逻辑的，而将其放到不属于内核空间也不属于用户空间的内存中是很危险的。
```
void PMM::move_boot_info(void)
{
    // 计算 multiboot2 信息需要多少页
    size_t pages = BOOT_INFO::boot_info_size / common::PAGE_SIZE;
    if (BOOT_INFO::boot_info_size % common::PAGE_SIZE != 0)
    {
        ++pages;
    }
    // 申请空间
    uintptr_t new_addr = get_instance().alloc_pages_kernel(pages);
    // 复制
    memcpy((void *)new_addr, (void *)BOOT_INFO::boot_info_addr,
           pages * common::PAGE_SIZE);
    // 设置地址
    BOOT_INFO::boot_info_addr = (uintptr_t)new_addr;
    // 重新初始化
    BOOT_INFO::init();
    return;
}
bool PMM::init(void)
{
    // .......

    // 将内核已使用部分划分出来
    if (alloc_pages_kernel(common::KERNEL_START_ADDR, kernel_pages) == true)
    {
        // 将 multiboot2信息移动到内核空间
        move_boot_info();
        vga_printf("pmm init.\n");
        return true;
    }
    
    //.......
}
```
到此完成了内存的初始化，现在内核可以进行内存的分配和释放了。
