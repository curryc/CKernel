# 构建问题：cmakelists中这段代码：
```
add_library(boot_grub_x86_64 OBJECT 
    idt/idt.S boot/boot.S )
```
会让第一个idt.S无法找到C中的符号，如果换位置会让boot.S无法找到C中的符号。非常奇怪。


# 更改platform构建方式后出现找不到port符号的错误
其他任何位置都找不到port库中的任何符号，但是能找到头文件，因此肯定是链接出了问题
## 解决方式：
这是典型的 「链接顺序」 问题，加上 「静态库只解析一次」 的 ld 特性：
libport.a 出现在 依赖它的库之前；
当 ld 处理到 libport.a 时，还没有任何未解析符号需要用到它；
等 ld 继续往后走到 libkernel_grub.a、libcommon.a、liblibc.a 时，才发现需要 port_inb，但 已经不会回头再去扫 libport.a；
结果就是：明明库里有符号，ld 却“看不到”。
因为我的库基本都是STATIC的，只解析了一次，所以需要注意顺序问题，只需要让cmake进行循环解析即可
```
            --start-group
            $<TARGET_FILE:boot_grub_x86_64>
            $<TARGET_FILE:kernel_grub>
            $<TARGET_FILE:common>
            $<TARGET_FILE:libc>
            $<TARGET_FILE:libcxx>
            $<TARGET_FILE:port>
            --end-group
```
其中的start-group和end-group中间的内容将会被循环解析，不会再出现链接错误
