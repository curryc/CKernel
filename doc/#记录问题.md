# 构建问题：cmakelists中这段代码：
```
add_library(boot_grub_x86_64 OBJECT 
    idt/idt.S boot/boot.S )
```
会让第一个idt.S无法找到C中的符号，如果换位置会让boot.S无法找到C中的符号。非常奇怪。

## 解决方式：
这是典型的 「链接顺序」 问题，加上 「静态库只解析一次」 的 ld 特性：
libport.a 出现在 依赖它的库之前；
当 ld 处理到 libport.a 时，还没有任何未解析符号需要用到它；
等 ld 继续往后走到 libkernel_grub.a、libcommon.a、liblibc.a 时，才发现需要 port_inb，但 已经不会回头再去扫 libport.a；
结果就是：明明库里有符号，ld 却“看不到”。
因为我的库基本都是STATIC的，只解析了一次，所以需要注意顺序问题，只需要让cmake进行循环解析即可
```
            --start-group
            $<TARGET_FILE:boot_grub_x86_64>
            $<TARGET_FILE:kernel>
            $<TARGET_FILE:common>
            $<TARGET_FILE:libc>
            $<TARGET_FILE:libcxx>
            $<TARGET_FILE:port>
            --end-group
```
其中的start-group和end-group中间的内容将会被循环解析，不会再出现链接错误

# 内核级错误：multiboot2中的正常代码会导致内核崩溃退出
```
uint32_t tag_size = mmap_tag->size;
uint8_t *tag_end = (uint8_t*)mmap_tag + tag_size;
uint32_t entry_size = mmap_tag->entry_size;
vga_printf("Tag size: %d, Entry size: %d\n", tag_size, entry_size);
MULTIBOOT2::multiboot_mmap_entry_t *mmap = (MULTIBOOT2::multiboot_mmap_entry_t *)
    ((uint8_t*)mmap_tag + sizeof(multiboot_tag_mmap_t));
int max_entries = (tag_size - sizeof(multiboot_tag_mmap_t)) / entry_size;
vga_printf("max_entries: %d\n", max_entries);
```
这段代码中任何变量都不能第二次使用，比如这里的max_entries，如果使用两次就会导致内核崩溃退出。
多调试后发现cpu发出了Triple Fault错误，也让我开始使用gdb进行调试。
这里如果把第一个打印代码：
```
vga_printf("Tag size: %d, Entry size: %d\n", tag_size, entry_size);
```
注释了，即他们只会在创建max_entries的时候打印一次，那么后续的max_entries就会正常打印。
## 解决方法：
在经过大量的调试后，排除了mmap_tag的相关的任何错误，比如内存访问越界，非法等错误，也排除了c++语言的语法、初始化错误。最终锁定在函数的栈上。发现我的构建存在两个问题：
1. 栈的方向错误：一开始设置cpu栈的方法如下
```
    // 设置栈地址
    mov $stack_top, %rsp
    // 栈地址按照 4096 字节对齐
    and $0xFFFFFFFFFFFFF000, %rsp
    // 帧指针修改为 0
    mov $0, %rbp
    // 初始化 C++
    call cpp_init
    call kernel_main
    hlt
    ret

// 声明所属段
.section .bss.boot
// 16 字节对齐
.align 16
.global stack_top
// 栈
stack_top:
    // 跳过 16KB
    .space 4096 * 4

```
这会导致栈向高地址增长，而不是向低地址增长。需要在设置rsp后加上
```
    add $4096 * 4, %rsp        # 指向栈顶
```
才可以正常工作

2. cpu抛出了invalid opcode错误，即尝试执行一个不存在的指令。
这是因为我的编译器生成了浮点指令，但是我的cpu不支持浮点指令，我并没有设置sse必需的寄存器位。
>
>SSE（Streaming SIMD Extensions） 是 Intel 在 1999 年推出的 浮点和向量指令集扩展，用于：
>加速浮点运算（float, double）
>向量运算（SIMD：Single Instruction, Multiple Data）
>内存拷贝优化（比如 memcpy 用 SSE 一次搬 16 字节）

x86_64系统默认是启用的SSE，浮点参数用xmm0~xmm7 传递。必须手动禁止才行，所以问题非常隐蔽，难以察觉。
所以这应该是一个编译优化的问题，我没有察觉到。
